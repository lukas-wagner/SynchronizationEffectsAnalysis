# SynchronizationEffectsAnalysis

Simulation and optimization code for the paper

> T. Hein, L. P. Wagner, A. Bernhard, F. Ocker, "Price-Optimized EV and Heat-Pump Scheduling Can Exceed Uncoordinated Feeder Peaks", accepted at IEEE IES ONCON 2026. Preprint: [arXiv:2610.05916](https://arxiv.org/abs/2610.05916), DOI [10.48550/arXiv.2610.05916](https://doi.org/10.48550/arXiv.2610.05916).

The study quantifies load synchronization on a rural low-voltage feeder when electric vehicles (EVs) and heat pumps (HPs) all optimize against the same electricity price, and compares this with uncoordinated charging and transformer-aware central scheduling.

## Overview

| | |
|---|---|
| Grid | SimBench `1-LV-rural2--0-sw` (97 buses, 99 loads, 250 kVA transformer) |
| Power flow | pandapower, Newton-Raphson, 15-min steps, 7-day horizon |
| Seasons | winter (week 3), spring (16), summer (29), autumn (42) |
| Optimization | Linear programs solved with Gurobi |
| Penetration | EV 0–90 %, HP 0–60 % (0–90 % without EVs), PV 0–60 %, in 30 pp steps |
| Robustness | reference case (30 % each) in all 52 weeks with the prices of 2022–2025, heterogeneous heat pumps |

### Scenarios

| Name | Description |
|---|---|
| `baseline` | Household load and PV only |
| `fixedsoc_times` | Each EV starts charging at 18:00 (or on later arrival) at full power until it is back at 45 kWh, HPs follow thermal demand |
| `fixedsoc_random` | As `fixedsoc_times`, but each EV starts at its own hour drawn once from N(18:00, 1.5 h) |
| `decentral` | One cost-minimizing LP per device against the intraday price, no grid awareness |
| `decentral_m3` | As `decentral`, plus the § 14a EnWG Module 3 time-variable grid fee (Q1/Q4) |
| `central_cost` | One joint LP minimizing total cost under a transformer limit |
| `central_peak` | One joint LP minimizing the peak transformer import |
| `fixed_times`, `fixed_random` | Legacy fixed strategies of the submitted version (arXiv v1): fixed 2-hour sessions without SoC limit, kept for reproducibility |

The `fixedsoc_*` strategies use the same EVs and trips as the optimized strategies and charge only while the EV is at home, so all strategies deliver the same trip energy. They replace the legacy fixed strategies in the final paper.

## Repository structure

```
config.json            master configuration (grid, devices, prices, solver)
run.py                 run single scenarios
run_sweep.py           run the penetration/season sweeps in configs/sweep_blocks.json
run_weeks.py           robustness runs over all weeks and price years 2022–2025 (output_weeks/)
run_het.py             heat-pump heterogeneity sensitivity (output_het/)
simulation/            scenario scripts, power-flow pipeline, plotting
optimization/          LP formulations (optimize_charging.py), price preprocessing
input/                 PV capacity factors and outdoor temperatures (Norderstedt) + build scripts
analysis/summarize.py  aggregates all runs into output/summary.csv
analysis/weeks_*.py    KPIs and delivered energy of the week runs
tests/                 unit, solver and integration tests (pytest)
```

## Installation

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

The optimized scenarios need a Gurobi license (free academic licenses are available).

## Usage

```bash
python run.py baseline              # single scenario with config.json
python run.py all                   # all scenarios into one output folder
python run_sweep.py --dry-run       # list the runs of the full study
python run_sweep.py                 # run all sweep blocks (skips finished runs)
python run_sweep.py Block1_core     # run a single block
python analysis/summarize.py        # write output/summary.csv
python run_weeks.py                 # 728 runs over 52 weeks x 4 price years
python analysis/weeks_analysis.py   # write output_weeks/weeks_summary.csv
python analysis/weeks_energy.py     # delivered energy per week (optimization only)
python run_het.py --normalized      # 25 runs with heterogeneous heat pumps
pytest tests                        # run the tests
```

Each run writes its power-flow time series (`*_results.json`) and plots to `output/<ev>_<pv>_<hp>_<season>_<scenario>/`. Results are not part of the repository and are regenerated by the sweep.

The final paper uses 913 runs: 160 main runs from `configs/sweep_blocks.json` (with the `fixedsoc_*` blocks in place of the legacy fixed runs), 728 week runs and 25 heterogeneity runs.

## Data

- **Electricity prices:** the paper uses 15-minute volume-weighted prices from the German continuous intraday market. These market data are licensed and **not included**. To use your own data, create `optimization/intraday_prices.json` with `optimization/build_prices.py <export.xlsx>`, or set `optimization.price_csv` in `config.json`. The main weeks use the prices of 2024. The week runs set `optimization.price_year` (2022–2025) and need prices for all four years, mapped by ISO week and weekday. Without a price file, the code falls back to the generic daily profile `price_profile_eur_per_kwh` in `config.json`, so results will differ from the paper.
- **PV and temperature:** derived from [Renewables.ninja](https://www.renewables.ninja/) (PV: CC BY-NC 4.0; temperature: NASA MERRA-2) for Norderstedt, Germany.
- **Grid fee:** § 14a EnWG Module 3 values from the Stadtwerke Norderstedt 2026 price sheet, set in `config.json`.

- **Heat-pump heterogeneity:** `hp.heterogeneity` in `config.json` (off by default) scales rating, COP, buffer and heating threshold per heat pump, with spreads after Fischer et al. (2017) and Brudermueller et al. (2025).

All random draws (device placement, mobility, start times, heat-pump parameters) use fixed seeds, so runs are reproducible.
